# 轨道基础设施功能栈：提议存档与融合方案

记录日期：2026-10-09。来源：用户提供的太空近地轨道资产分层提议；本轮经公开原文核对并融合至项目定义。
状态：分类与数据协议增补，未改变线上栏目、既有数值或预测。不是行业统一标准，也不是三家机构共同发布的五层模型。

## 1. 保存原提议的核心内容

提议以 NFX、Amadeus Capital、Space Capital 的产业栈观点为参考，将资产组织为五类功能：

| 原层级 | 用户提议名称 | 原典型场景与载荷 | 原 IT 类比 |
|---|---|---|---|
| L0 | 时空物理底座 | GNSS、原子/光钟、ICRF、引力/相对论修正；约 20,000 km MEO 与地基网 | 系统时钟与绝对寻址 |
| L1 | 动态互联总线 | 300–550 km 中倾角 LEO、100 Gbps+ 激光星间链路、路由器、相控阵 | 网络总线、InfiniBand/PCIe |
| L2 | 能源与算力中心 | 600–800 km 晨昏 SSO、200 kW+ 光伏、辐射散热排、AI 卡与轻量容器环境 | GPU/NPU 集群 |
| L3 | 泛在感知输入 | 对地光学/SAR/SIGINT、对轨 SDA、天文/太阳观测；10:30 SSO 等 | I/O 传感器 |
| L4 | 物理操作与在轨服务 | 拖船、加注、机械臂、拼装、捕获与碎片清除；RAFTI 等接口 | 执行器与垃圾回收 |

原商业假说一并保留：共享通信/计算/物流可能减少重复建设；不同轨道适配不同任务；未来可能出现算力租赁、轨道物流与观测数据 API 的 PaaS/IaaS 模式。以上是设计愿景和待验证商业假说，不是现有资产统计或经济预测。原提议中的功率、速率、延迟和轨道区间没有被直接导入指标。

## 2. 原始参考核验与归因

访问日期均为 2026-10-09。以下只作为分析框架参考，不能据此生成在轨资产数量或性能值。

- [NFX — The Stack Above the Cloud](https://www.nfx.com/post/stack-above-the-cloud)，Morgan Beller / Daniel Museles，原文标注 2026 年 2 月。讨论发射、卫星制造、数据与计算及 PNT 等基础设施机会；并非本文五层的逐层定义。
- [Amadeus — Space Tech Stack 2025: Mapping Value from Ground to Orbit and Back](https://www.amadeuscapital.com/space-tech-stack-2025-mapping-value-from-ground-to-orbit-and-back/)，James Baker，2025-07-23。价值链含地面、下游服务、制造、发射、在轨服务/可持续性及返回物流；不等于将 Edge AI、光链路、数据 API 定义为本文层级。
- [Space Capital — Space IQ Methodology](https://www.spacecapital.com/space-iq/methodology)：正式框架为 Infrastructure / Distribution / Applications，并另有产业、赛道分类。GPS、GEOINT、SatCom 是赛道，不是本文 L0–L4；“The Space Economy Taxonomy”按主题参考保存，不冒称已定位同名独立白皮书。

物理与口径核验参考：

- [GPS.gov — Space Segment](https://www.gps.gov/space-segment)：GPS 的典型高度约 20,200 km，属于 MEO，说明不能把所有支撑层称为 LEO 实体。
- [NASA — Small Spacecraft Thermal Control](https://www.nasa.gov/smallsat-institute/sst-soa/thermal-control/)：热平衡需要同时考虑入射太阳、地球辐射、表面特性及排热；真空不能靠对流散热。
- [ESA — Dawn-dusk orbit space-weather study](https://swe.ssa.esa.int/TECEES/spweather/esa_initiatives/spweatherstudies/ALC/WP2400_report_v1.pdf)：提供晨昏轨道 eclipse 条件分析；实际光照需要逐轨道、逐季节验证。

## 3. 采纳及修订

**命名与边界：** 采用“轨道基础设施功能栈 / Orbital infrastructure functional stack”。LEO 是重点，不是所有层的轨道限制。L0–L4 是功能标签，不是高度层、成熟度等级或必须依次实现的工程路线。

**保留五个功能标签：** L0 定位/授时/参考服务；L1 通信/中继/互联；L2 能源与计算（分别记录 power、compute 子角色）；L3 感知/观测；L4 机动物流与在轨服务。制造和回运另设跨层 capability 标签，不因模型未给独立层就从资产范围消失。

**资产多标签、总量去重：** 同一卫星可承担 L1/L2/L3；以稳定 assetId 计一次物理数量和质量。主功能只用于互斥汇总，次功能用于筛选；多标签图必须提示不可相加。星座品牌、代际、卫星、申报网络和链路不是同一级实体。

**物理事实不绑定 IT 比喻：** 激光链路不是通用 PCIe/InfiniBand 等价物；精确 GNSS 不是每条光链路的唯一前提。ICRF/UTC 是参考体系而非可按卫星颗数累计的资产；链路还依赖相对导航、捕获跟踪与指向能力。

**移除确定性推断：**

- 晨昏 SSO 是候选光照条件，不自动等于全年无食；计算也不被限定在 600–800 km。
- 深空可作为辐射冷源，但不会消除散热器面积、姿态、太阳/地球入热、辐照和能源储存约束。
- L1 不能限于中倾角 300–550 km；极轨/高倾角 LEO、GEO 中继及地面接口均可能参与。
- 10:30 不是全部遥感的唯一最佳轨道；SAR、SDA、天文与光学任务分别保存真实轨道。
- 200 kW、100 Gbps、20–30 ms、纳秒级精度均须逐资产/产品保存证据与测试条件，不能成为整层默认值。
- L3 必须保留直接下传、地面站及非共享网络方案。不能因为存在 L1/L2 就假定已经解耦。
- “指数级降本”“杜绝多任务损害”“解决热力学矛盾”降为待验证假说；不进入预测计算。

## 4. 与现有看板融合

现有五大栏目不重排，功能栈作为“在轨资产”的第二分类维度：

| 栏目 | 融合方式 |
|---|---|
| 发射信息 | 保持真实任务、运力与成本口径；用载荷 assetId 关联功能标签，不将每层重复计为一次发射 |
| 地面/海洋发射基地 | 作为接入资产；地面通信站与参考网另标 ground，不冒充在轨质量 |
| 在轨资产/星座 | 同时保留用途、轨道、运营者、库存/质量；新增功能标签。星座进度主要关联 L1，不能自动把整星座标为商业算力 |
| 载人&地月 | 已核验的电源、计算、观测、物流作为跨栏目实体引用；同一空间站/飞船不重复造实体 |
| 卡尔达肖夫 | 不由分层标签或峰值装机功率推算文明进度；能源边界、实际平均功率及双计问题单独处理 |

制造或 compute 的工业成果必须有实际交付、运行工作负载或完成服务的证据。一般遥测处理器不是可租用数据中心；技术演示不等于持续运营。L4 服务范围可包含其他轨道，但应明确场所和目标，不将 GEO 服务统计为 LEO 服务。

## 5. 指标与状态协议

| 功能 | 首批应追踪的原始指标 | 避免的替代口径 |
|---|---|---|
| L0 | 节点数量、服务覆盖、已公布定位/授时性能及测量条件 | 未经条件说明的统一纳秒精度 |
| L1 | 在轨节点、具备 OISL 节点、已确认链路/终端、单链路实测速率 | 全终端标称速率相加为全网吞吐 |
| L2 | 计算节点/载荷、任务与工作负载、可用功率/平均功率、已测性能及精度 | 计划装机算在役算力；混合 FLOPS/TOPS/精度 |
| L3 | 在轨观测资产与质量、传感器类型、分辨率/重访/数据产品延迟 | 数量替代感知能力；全部光学 SAR 混成一项分数 |
| L4 | 在役服务载具、已完成交会/服务/转移事件、已证实转运质量 kg | 把合同/设计容量当实际加注通量 |

字段级区分 planned / ground_test / launched / in_orbit_demo / operational / inactive / retired / unknown，分别保存日期和证据。状态不是自动递增进度条；已入轨不自动证明工作，未披露不是零。

基础字段：assetId、parentEntityId、entityKind、countryGroup、operator、realm、orbitRegime、primaryLayer、secondaryLayers、capabilities、status、statusAsOf、sourcePublishedAt、retrievedAt、evidenceLevel。观测值记录 metric、value、unit、measurementBasis、precision、testConditions、aggregationScope、sourceUrl、asOf；未知 value=null。关系另存 provides_service_to / communicates_with / supplies_power_to / computes_for / services，允许规划/演示/实用关系各自留证。

**不能自动分类：** GCAT COM/NAV/IMG 可提供 L1/L0/L3 候选，但需要核验角色；TECH 或 SS 不能直接证明 L2/L4。目录质量/数量继续用现有分类，不回填未经证明的功能历史。

## 6. 实施边界和下一步

本轮已落地：本提议档案、规范化分类 JSON、现有 spec 的增补入口、参考范式索引。JSON 不包含新计数或虚构资产，不被每日数据脚本当成实时来源。

后续前端实施切片：在轨资产内增加功能筛选/摘要，底部给出成熟度和缺失值；L0/L1/L3 有数据先展示，L2/L4 先以有证据资产和事件列举。随后收集实际计算与制造成果，才形成工业能力专题。暂不增加 3D 轨道、统一指数、资源消耗推算或财务估值。

开放问题：实际哪些资产有共享服务依赖证据？计算算力/功耗能否按可比条件采集？制造、回运、GEO 服务如何在主范围中分组？这些不因写入模型就视为已有数据。

## 7. 展现形式讨论：看板与空间模拟（2026-10-09）

用户提出是否从 dashboard 转向真实模拟视图，参考 [Starlink Mission Control](https://huggingface.co/spaces/juliensimon/starlink-mission-control)。后续确认先实施看板内容与功能关系图；空间视图仅研究范围聚焦且覆盖 Starlink 之外对象的既有项目，暂不实施模拟。

核验其 [项目说明](https://huggingface.co/spaces/juliensimon/starlink-mission-control/blob/main/README.md)：使用 CelesTrak TLE 与 SGP4 推算位置；真实终端遥测需接入自己的 Starlink 终端，否则存在模拟模式。ISL 路由是估计，作者明确没有内部调度、实际链路路由及单星负载等信息。不能把动画等同全网实时遥测或经过验证的网络数字孪生。其 fleet 历史分析可作为壳层分布与部署进度的范式参考。

建议三种视图共享同一资产主表及来源协议：

- 看板默认：保留数量、质量、部署与监管进度、运行证据和事件。
- 功能关系图：表达 L0–L4 服务提供者/使用者与缺失基础设施，不按层级排列制造虚假轨道高度；只画有证据的关系，已实现与计划/假设分别标识。
- 可选空间视图：首批展示有轨道要素的代表性星座、轨道壳层与地面站，支持时间播放及对象选择。点选资产联动原始指标、状态与证据。没有逐星轨道的数据只显示明确标注的聚合分布，不合成“真实”卫星位置。

空间仿真优先回答具体问题：部署填充/高度变化、某地点几何可见性、选定资产的日照与食段。覆盖推算需公开高度、仰角、时间等参数；几何可见不等于可用业务容量。L2 工作负载、实际电力/吞吐与 L4 交付依赖运行记录，不能从轨道位置推断。

建议首个切片为“功能栈摘要＋可筛选资产＋二维轨道分布”，随后按需加入少数星座 3D 空间探索。日更轨道快照可在浏览器中连续推进，不要求持续请求上游；必须展示轨道要素历元、数据获取时间、推算时间及过期提示。多年历史播放需要历史轨道要素，不能反向传播当前要素冒充历史观测。性能上按需加载、抽样/聚合并提供移动端二维回退。

未决事项：用户更希望研究空间分布、服务依赖还是覆盖/日照？是否需要独立探索入口？具体第一批可核验资产与轨道数据覆盖须先盘点。暂不承诺精确全网链路、碰撞预警或资源调度数字孪生。

## 8. 1.7.0 实施记录与空间视图候选

已加入在轨资产板块：五层功能摘要、层级筛选、五组关系实例、可点选节点、逐条关系的来源与事件/发布日期、核验实例清单，以及参考框架/数据协议入口。六条关系覆盖 EDRS 观测中继、Φsat-2 星上 AI、MEV-2 延寿、鹊桥二号与嫦娥四号通信测试、GPS 用户服务架构。11 个功能节点不等于 11 颗卫星；同一卫星搭载的多个载荷有共同父实体。

GCAT 通信、导航、对地观测数量仅作为 L1/L0/L3 分类代理；L2/L4 未取得全球可比总量，保留未知。历史成果不自动标为当前运营，不虚构跨星算力、能源依赖或加注关系。本轮未刷新既有库存快照。

空间视图仅作候选研究，未接入或部署第三方程序：

| 项目 | 可借鉴范式 | 范围与限制 |
|---|---|---|
| [NASA Eyes on the Earth](https://eyes.nasa.gov/apps/earth/) / [官方介绍](https://www.nasa.gov/earth-and-climate/nasas-eyes-on-the-earth-puts-the-world-at-your-fingertips/) | 任务选择 → 资产轨道 → 所提供的观测数据，适合作为 L3 范式 | 聚焦 NASA 对地观测任务，不是中美资产全集；未确认可复用源码许可证，先作展示参考 |
| [SatelliteMap.space](https://satellitemap.space/vis/constellation/oneweb) | 以星座为入口，结合地面站、轨道及库存信息 | 页面列出 GPS 等网络并提供 OneWeb 路由；部分事件/发射功能标为待上线，实际非 Starlink 数据覆盖仍需交互核验；不据此声称覆盖国网/千帆或源码可复用 |
| [Satvis](https://github.com/Flowm/satvis) | 以可配置分组或指定对象创建专题预设，开关轨道、地面轨迹与站点 | MIT 开源；默认目录较广，不宜照搬默认视图。说明支持 GNSS、气象、对地观测、空间站等分组和自定义预设；适合作为限定资产集的技术候选，不是已验证的服务链仿真 |

建议先讨论“专题资产空间视图”：默认仅加载所选角色/资产，不画碎片；点选资产联动已有数量、状态与关系证据。轨道推算、几何可见性和已证实的服务关系必须分开标识。第三方页面称实时的位置不等于持续逐星遥测；Satvis 明确以 CelesTrak GP 要素在浏览器内做 SGP4 推算。尚未执行候选项目的完整交互验收或中国星座覆盖盘点。
