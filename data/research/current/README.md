# 大型星座本地数据核验包

采集日：2026-09-26。此目录尚未接入 dashboard，未触发版本发布。

## 三份数据

1. [constellation-registry.json](constellation-registry.json)：主要大型星座基本信息、规模依据、分阶段计划、商业运营证据和当前在轨快照。
2. [itu-milestones.json](itu-milestones.json)：ITU 规则、申报身份与版本、BIU 事件、M0—M3、部署节点和材料提交截止日；FCC 节点保存在独立上下文，不混为 ITU 期限。
3. [filing-deployment-progress.json](filing-deployment-progress.json)：每个申报追踪单元的官方状态表数、历史部署报告、频段数量门槛、轨道平面及已恢复的逐星名称。

本批优先覆盖星链、Amazon Leo、OneWeb、国网、千帆，并非全球所有 1000+ 提案的完整目录。规模门槛可来自企业计划、ITU 通知或国内授权，但必须注明依据。OneWeb 以 L5 通知规模纳入，不代表现有运营星座超过 1000 颗。E-Space、银河、PWSA 放在待核验观察名单；未把巨大纸面申报当成确定建造计划。

## 标杆定义

- 申报接收、发布、修订：记录 SNS、特别节和 IFIC；历史版本保留，分母不沿用旧版。
- BIU（点亮）：按频率组记录正式使用日期，区别于首发时间。90 天持续使用证据、主管部门确认、ITU 结论是不同证据。
- M0：初始部署信息，不等于“点亮”事件，也没有固定百分比门槛。
- M1 / M2：按有效通知和适用频段的 10% / 50%，向下取整。保留官方报告中的 BR130 门槛。
- M3：100% 的计数规则允许少一颗（resolves 4），仍须保留逐轨道平面的配置证据；不能套用粗略品牌总数。
- 部署节点 ≠ 材料提交截止日：一般部署节点后 30 天；旧系统过渡情形的规则明确为 2 月 1 日，不能统一机械加 30 天。
- 低于门槛时的修改提交、RRB 例外、暂停、替换和退役需单独追踪。完全部署后仍有报告义务，不是到 M3 即结束。
- 近期有效版的配置和逐星归属未核实前，当前合格数量、完成率和所需月均部署量均留空。

## 核验结果与缺口

运行：

```sh
node scripts/validate-constellation-data.mjs
node scripts/validate-constellation-data.mjs --self-test
```

结果：470 项结构 / 数值 / 口径检查通过；6 个故意破坏的回归样本被拒绝。状态为 `PASS_WITH_GAPS`，不是“全面数据验证通过”。五份报告的 514 条轨道平面计数分别与官方总表一致。

主要缺口：

1. 所有申报的“今日合格部署数量”仍待逐星归属和现行通知核验；今天的 GCAT 品牌库存不能直接替代。
2. L5Ku 清单 279 与本次 M1 报告 269 不一致，两者均保留；L5Ka 的频段分母为 720，不能直接使用总表 2692。
3. L5Ka 279 行卫星记录只有 278 个唯一名称，SL0192 重复；STEAM-2B 新版报告的名称尚未被当前解析器恢复。不得用它们生成已完成的逐星映射。
4. USASAT 8B、8C 的上游 `new_sat_name` 都写成 8A，已保留异常，身份使用原始 `sat_name`。Ofcom 2024 版 1156 / 1292 与现清单 1154 / 1294 也不是同一版本。
5. 国网协调请求与实际 Notification 不能混同；当前通知分母、BIU 与期限待补齐。SAILSPACE-1 与千帆的直接官方品牌映射待确认。
6. 商业运营信息仍不完整；用户量、收入、覆盖、服务起始各自需要日期和运营商披露。

可用于下一轮评审的内容：有日期的物理库存、注明口径的计划数、官方申报状态与日期。暂不启用：合规进度条、法律红绿灯、跨申报求和与部署速度预测。

## 手工维护方法

1. 每周读取 GCAT 各子组，保存独立观测日期；不回填成伪历史。
2. 下载 ITU RES35 清单公开 bundle，以数据字面量解析，不执行上游 JavaScript，保存哈希及清单更新时间。
3. 核对 SNL 修订与有效 Notification；遇到新部署报告，保存 URL、哈希、收到日、发布日与实际统计日。
4. 官方 PDF 可缓存到临时目录，再使用 `scripts/extract-constellation-reports.py`（依赖 pypdf）读取。自动抽取仅作初筛，必须核对平面合计、频段门槛、名称重复和版式变化。
5. 更新三份 JSON，运行上述核验与回归测试。历史快照 `../constellations-2026-09-26.json` 保留不改写。

此阶段不需要自动采集部署。待缺口与呈现口径评审后，再集成 dashboard 并按既定规则公开发布新版本。
